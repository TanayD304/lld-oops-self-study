# Study Strategy

> "Don't study to finish the syllabus. Study until you think like a software engineer."

---

# Goal

This repository is not just for interview preparation.

Its purpose is to build the ability to design clean, maintainable and extensible software while preparing for Google SDE-2 level interviews.

Every topic will be learned deeply enough to explain, implement, review and apply in real systems.

---

# Learning Philosophy

```
Learn
    ↓
Think
    ↓
Visualize
    ↓
Implement
    ↓
Review
    ↓
Refactor
    ↓
Interview
    ↓
Revise
    ↓
Apply in Machine Coding
    ↓
Repeat
```

Reading alone is not learning.

Writing code alone is not learning.

Real learning happens when implementation, review and reflection are combined.

---

# Session Workflow

Every session follows the same structure.

## 1. Overview

* Definition
* Why the concept exists
* Problems it solves
* Interview definition

---

## 2. Intuition

* Real-world analogy
* Motivation
* Evolution of the concept

---

## 3. Internal Working

Understand:

* Compiler behaviour
* Runtime behaviour
* Memory layout
* Stack vs Heap
* Object lifecycle
* Performance implications

---

## 4. Visualization

Whenever applicable create:

* UML diagrams
* Mermaid diagrams
* Memory diagrams
* Object relationship diagrams
* Sequence diagrams

If you cannot draw it,
you probably don't understand it.

---

## 5. C++17 Implementation

Always implement:

* Basic version
* Improved version
* Production-quality version

Focus on:

* Modern C++
* Clean naming
* Encapsulation
* Const correctness
* Best practices

---

## 6. Code Review

Every implementation is reviewed.

Review focuses on:

* Design quality
* Readability
* Extensibility
* Maintainability
* Performance
* Common interview mistakes

Never move to the next session without review.

---

## 7. Best Practices

Understand how experienced engineers solve the same problem.

Avoid learning only the academic definition.

---

## 8. LLD Connection

For every concept ask:

* Where is it used?
* Why does it matter?
* Which systems depend on it?

Examples:

* Parking Lot
* Splitwise
* Library
* ATM
* BookMyShow

---

## 9. Design Pattern Connection

Understand which design patterns depend on the current topic.

Learning should always be connected.

---

## 10. Interview Preparation

Every session includes:

* Basic questions
* Intermediate questions
* Advanced questions
* Google-style follow-up questions

Do not memorize answers.

Understand the reasoning.

---

## 11. Practice

Every session includes four levels.

### Level 1

Implementation

### Level 2

Object Modelling

### Level 3

Refactoring

### Level 4

Design Challenge

---

## 12. Revision

Prepare:

* One-page notes
* Cheat sheet
* Flashcards

Revision should take less than 10 minutes.

---

## 13. Self Assessment

Before moving ahead, verify:

* I can explain it.
* I can implement it.
* I know internal working.
* I know common mistakes.
* I know interview questions.
* I know production usage.
* I can apply it in LLD.

If any answer is "No", revisit the topic.

---

# Additional Learning Rules

## Think before coding

Never start coding immediately.

First identify:

* Classes
* Responsibilities
* Relationships
* Future extensions

---

## Learn the "Why"

Definitions are easy to memorize.

Understanding why the concept exists makes it unforgettable.

---

## Draw Everything

If a concept involves relationships or flow, draw it.

Visualization improves retention.

---

## Refactor Often

The first solution is rarely the best.

Improve the design after it works.

---

## Prefer Understanding over Speed

Finishing the roadmap quickly is not the goal.

Being able to solve unseen interview problems confidently is.

---

## Learn Like an Engineer

Don't ask:

> "What is the answer?"

Ask:

> "Why was this designed this way?"

# Success Criteria

I consider a topic complete only if I can:

* Explain it from first principles.
* Implement it without reference.
* Identify where it is used.
* Explain trade-offs.
* Refactor poor implementations.
* Apply it in Low Level Design.
* Teach it to someone else.

Only then move to the next session.
